# Vendored Libraries

Third-party libraries vendored in `js/lib/`. The new tab loads each of the four single-file libraries at its first use, as a classic script the page's loader puts in (`LIBRARIES` in `js/runtime/lazy.js`, #27 slice 3), and the build copies them to `dist/js/lib/` byte for byte, license headers included (`CLASSIC_SCRIPTS` in `scripts/build/vite-config.js`). Valibot is an ES module the bundler folds into the chunks that import it. Each library's version, copyright, and full license text, and those of the components bundled inside it, are in [`THIRD_PARTY_NOTICES`](../../THIRD_PARTY_NOTICES) at the repository root, which ships in the package.

| ----------------- | -------------------- | ------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `chart.js`        | Chart.js             | 4.4.1   | MIT                                              | https://www.chartjs.org / [jsDelivr](https://cdn.jsdelivr.net/npm/chart.js@4.4.1/dist/chart.umd.js)              | Analytics dashboard charts                               |
| `fuse.js`         | Fuse.js              | 7.1.0   | Apache-2.0                                       | https://fusejs.io / [npm](https://www.npmjs.com/package/fuse.js/v/7.1.0)                                         | Lightweight fuzzy search for sidebar and command palette |
| `jszip.min.js`    | JSZip                | 3.10.1  | MIT (dual MIT or GPL-3.0; used under MIT)        | https://stuk.github.io/jszip / [npm](https://www.npmjs.com/package/jszip/v/3.10.1)                               | ZIP archive generation for bulk export                   |
| `transformers.js` | @xenova/transformers | 2.17.1  | Apache-2.0 (bundles MIT, BSD-3-Clause, ISC code) | https://huggingface.co/docs/transformers.js / [npm](https://www.npmjs.com/package/@xenova/transformers/v/2.17.1) | Local embedding generation for semantic search           |
| `valibot/`        | Valibot              | 1.5.0   | MIT                                              | https://valibot.dev / [npm](https://www.npmjs.com/package/valibot/v/1.5.0)                                       | Schemas for the kernel's message contracts               |

`transformers.js` is the package's `dist/transformers.min.js` with its closing `export{...}` statement replaced by `window.transformers=__webpack_exports__;`, so it loads as a classic script. `chart.js` is the package's `dist/chart.umd.js` as jsDelivr serves it, with the comment jsDelivr adds at the top. Both have their closing `//# sourceMappingURL` line deleted, since the maps don't ship. `fuse.js` and `jszip.min.js` are unmodified upstream builds.

`vendor.json` records each of these files' package, version, license, source, SHA-256, license banner, `THIRD_PARTY_NOTICES` heading, and local edits, with the SHA-256 before each edit made here. `test/vendor.test.js` checks the files against it, and the build fails when a shipped or bundled file differs from its record, has none, or lost its banner.

`valibot/` holds the valibot package's `dist/index.mjs`, its `dist/index.d.mts` declarations, and its `LICENSE.md`, unmodified. The bundler folds `index.mjs` into the chunks that import it, the build ships `LICENSE.md` at `js/lib/valibot/`, and the declarations are only for type checking. `valibot/vendor.json` records the npm tarball and its integrity, and each file's path in it and SHA-256, which `test/kernel/vendor.test.mjs` checks. To check the copy against npm, run `npm pack valibot@1.5.0`, which prints the tarball's integrity, extract it with `tar -xzf valibot-1.5.0.tgz`, and compare `shasum -a 256` of each file's path with the record.
